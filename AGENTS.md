# Repository Guidelines

## What this repo is

An unscaffolded template whose only content is cross-tool AI agent configuration. There is no application code, no build system, no lockfile, and no CI job that runs tests. Do not invent commands (`make test`, `npm test`, …) — none exist yet.

Note: `main` currently has **no commits**, and `git ls-files` is empty. Every file here is untracked.

## Agent config layout

- `AGENTS.md` — the single source of truth ([agents.md](https://agents.md)).
- `CLAUDE.md`, `GEMINI.md` — deliberate pointers to `AGENTS.md`. Never duplicate guidance into them; edit `AGENTS.md` instead.
- `.claude/`, `.codex/`, `.cursor/`, `.gemini/`, `.github/gemini.yml` — per-tool config, intentionally near-empty placeholders. Leave them empty unless a change is actually needed.
- `.cursor/rules/project.mdc` — `alwaysApply` rule; its content is mirrored in "Workflow" below.
- `.gitignore` ignores `.claude/settings.local.json` and `.opencode/opencode.jsonc` (per-developer settings). Follow that pattern for any new tool-local settings file.
- `.opencode/.gitignore` is generated by opencode for its own scratch files. Do not hand-edit.

## Workflow (non-negotiable)

- Work in a `git worktree`. Never commit directly on `main`.
- Pull `main` and rebase onto it before finishing work.

## OpenCode specifics

There is **no root `opencode.json`** — all opencode config lives in `.opencode/`, and both files below are loaded and deep-merged:

- `.opencode/opencode.json` — committed, shared settings only.
- `.opencode/opencode.jsonc` — **gitignored** per-developer overlay; wins on conflicting keys. Setup: `cp .opencode/opencode.jsonc.example .opencode/opencode.jsonc` and edit.

Machine-specific provider values (AWS region/profile) belong only in the overlay.

- The example overlay targets Amazon Bedrock in `us-west-2` with AWS profile `ai3`. Model calls fail without that local profile; fix it in your overlay, never by committing values into `.opencode/opencode.json`.
- Config is read once at startup, so restart opencode after editing either file. Verify the merged result with `opencode debug config`.
- `{env:VAR}` substitution works in config strings, but an unset var resolves to `""` — an empty `region`, not the documented `AWS_REGION`/`us-east-1` fallback. A `{file:path}` whose target is missing is a hard startup error. opencode does not load `.env` files.
- If a config file is malformed and opencode won't start, `OPENCODE_DISABLE_PROJECT_CONFIG=1 opencode` skips both project files.

## When adding a toolchain

Scaffolding this template is the expected first real change. When you do:

- Commit the lockfile and the formatter/linter config (no editor-only settings).
- Document the canonical commands in `README.md` (does not exist yet) and update this file's command section.
- Expose the same commands in CI.
- Use `src/`, `tests/`, `docs/`, `assets/`; mirror source paths in the test tree (`src/auth/session.*` → `tests/auth/session_test.*`).
- Put slow or service-dependent tests under `tests/integration/`.

## Conventions

- Two spaces for YAML, JSON, and Markdown lists; otherwise defer to the language formatter.
- Imperative commit subjects; Conventional Commit prefixes are acceptable (`feat: add template renderer`).
- Never commit credentials or environment-specific secrets; provide a sanitized `.env.example` and gitignore the real file.
